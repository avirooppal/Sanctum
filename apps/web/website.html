Do I need a cloud account?

No cloud account is used by the local reference. Open the application and enter the local access key from the runtime's printed token-file path. The browser holds it in memory.

Does everything work offline?

The configured runtime uses local artifacts. Developer dependency and model provisioning require explicit downloads beforehand. A signed, fully verified offline release bundle is still pending.

What can I use today?

The working reference supports chat, cited document answers, saved conversations, file transcription, dictation, audio playback and reviewed meeting capture. It does not yet provide the complete live voice, vision or governed-agent experience.

Is it free?

Sanctum is open-source software. Local inference uses your hardware; the project reviews dependency and model licenses. No paid cloud subscription is required by the local reference.

Where is the desktop download?

Windows EXE and Linux release packages are not verified yet. This page deliberately offers working setup information instead of a nonfunctional download.

DEVELOPMENT SETUP

Bring your own machine.

Use Linux x86_64 or WSL Ubuntu 22.04 with user/network namespaces, glibc, libstdc++, libgomp and libssl3. Follow the repository's README.md to prepare models, engine binaries and the web build, or copy an already prepared development bundle into an empty directory.

  1. From the prepared bundle directory, run bin/sanctum-runtime --config profiles/runtime-cpu.json.
  2. Open the loopback address printed by the runtime (default port 8765). Startup must pass artifact verification and egress self-tests.
  3. Enter the key from the printed token-file path. Select an available model and send your first message.

These instructions assume provisioned artifacts; they are not a one-line installer. The source checkout README.md includes dependency installation and model provisioning commands. Never share your local key.
