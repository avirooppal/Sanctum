Sanctum Technical Documentation

Sanctum is an on-device, single-owner AI platform designed for total privacy. All compute runs on local CPU/GPU hardware; no telemetry or unreviewed cloud connectors exist.

1. Kernel Containment & Security Boundary

On Linux, Sanctum enforces isolated execution using unprivileged user namespaces, network namespaces (loopback-only with egress denial), and seccomp system-call filters.

# The Linux runtime checks deny-by-default egress before serving:
bin/sanctum-runtime --config profiles/runtime-cpu.json

2. Gateway Contracts & Authentication

All communication with the background daemon occurs through an authenticated gateway bound strictly to 127.0.0.1. Authentication uses a local token generated per launch and stored with restricted permissions.

  • POST /v1/chat/completions — Local text inference stream
  • GET /v1/models — Discovered local models and license verification
  • POST /v1/workspaces — Local vector & document storage
  • GET /healthz — Local daemon health and containment verification

3. Chat Renderer & Slash Commands

The web chat interface connects directly to the local daemon and supports markdown rendering with strict XSS sanitization (scripts and remote tracking images blocked). Built-in slash commands:

  • /help — List available local commands
  • /clear — Clear transcript memory
  • /stop — Abort in-flight inference
  • /info — Display active local model and security state

4. Knowledge Retrieval (RAG)

Local document ingestion processes Markdown and PDF files entirely on-device, indexing chunks into an embedded vector store. Questions generate grounded answers with verbatim citations.

5. Quality & License Gates

Every commit must pass 157 source tests, 62 Rust foundation tests, and comprehensive web tests with zero npm audit vulnerabilities and only permissive (MIT, Apache-2.0, BSD, OFL) licenses.

6. Platform Support Matrix & Release Blockers

In accordance with docs/RELEASE_CHECKLIST.md, native Windows packages, macOS MLX adapters, hardware voice pipelines, and GPU backends remain UNVERIFIED release blockers. The only verified environment is the Linux x86_64 / WSL reference running locally.
